# Spec N1 · 导出支持视频（音频 / 视频带音轨 / 视频纯视频）（2026-10-02）

> **状态**：**已批准并实现（2026-10-02）**；D3 的 ⏳ 已由实测收敛（见节末收口注记）。
> **来源**：用户 2026-10-02 原话「现在导出只导出音频吗？为什么不是音频视频一起可以导出……视频的选项包括纯视频和带音轨」，见 `docs/prds/剪辑体验改进需求-2026-10-02.md` N1 节。
> **关联**：依赖 Spec C（clip-works）已落地的成品归属（`source_work_id`）与导出任务链；不改 Spec C 已定语义。

---

## 1. 目标（用户要什么，一句话）

导出时用户可以选**导出什么**：

| 选项 | 含义 | 现状 |
|---|---|---|
| **音频** | mp3 / m4a / wav，分多段或合并 | **现状，行为不许有任何回归** |
| **视频 · 带音轨** | 按剪辑段切出 mp4，保留画面 + 声音 | 新增 |
| **视频 · 纯视频** | 按剪辑段切出 mp4，**去掉声音**（`-an`） | 新增 |

「导出什么」与既有两个维度（**分多段 / 合并成一段**）**正交**，可自由组合（视频合并 = 一条完整 mp4）。

## 2. 事实（设计依据，全部已核实）

1. **整条导出链现在是"音频形状"**：`ExportJobPayload.format` 只有 `'mp3'|'m4a'|'wav'`（`server/src/media/ffmpeg-export.ts:23`）；`runClip` / `buildMergeArgs` 只出音频；入库 `ingestDownloadedFile` 写 `audio_items`。
2. **成品表没有视频维度**：`audio_items`（`server/src/db/schema.ts:18-35`）有 `format/duration_sec/file_size`，无"是否有画面/分辨率"字段。**视频产物入库必须迁移**——这是本 spec 最大的决策点。
3. **任务事件已支持视频**：下载完成事件 `kind:'video'` 已存在（`library.tsx` 的 `onDone` 已分支），SSE 通道不用扩协议，只扩 `kind` 取值。
4. **素材音轨通常是 AAC**（B 站下载管线固定产出）→ 带音轨导出可尝试 `-c:a copy`（零重编码、零音质损失）；**须实测**确认与 mp4 容器兼容。
5. **重编码耗时要实测**：21:30 / 2.1GB 素材全片 H.264 重编码预计 10 分钟级（参考：N0 实测仅解码就 45s）。**导出比音频慢两个数量级是预期内事实**，UI 必须如实传达（进度条 + 任务抽屉已有，够用）。
6. **前端成品明细用 `<audio>` 播放**（`studio-detail.tsx`）——视频行必须分流渲染，否则视频产物"看不见"。

## 3. 裁决（每条含理由；标 ⏳ 的是留给实测/用户推翻的点）

### D1 · 数据模型：`audio_items` 加列，**不开新表**
```sql
ALTER TABLE audio_items ADD COLUMN media_kind TEXT NOT NULL DEFAULT 'audio'
  CHECK (media_kind IN ('audio','video'));
ALTER TABLE audio_items ADD COLUMN width INTEGER;   -- 视频才有；音频 NULL
ALTER TABLE audio_items ADD COLUMN height INTEGER;
```
- **理由**：成品的删除 / 试听 / 归属（`source_work_id`）/ 任务联动 / 安全网逻辑全是"按行操作"，加一列让**展示层**按 kind 分流，远比维护第二张表便宜。新表意味着成品列表、删除链、作品聚合（`product_count`）、hover 预览、首页全部要第二套路径——两倍面积换不来任何用户可见价值。
- **表名不改**（沿用 `clip_projects` 先例：名不符实但迁移成本为零），UI 术语统一叫「成品」。
- 迁移机制**复用 Spec C T1 既有模式**（备份 → ALTER → 幂等 → 老库升级用例）。
- ⏳ 若实测发现视频还需要更多字段（如 `vcodec`），在 plan 阶段再加，不在 spec 层扩。

### D2 · 导出参数：payload 加 `mediaKind`，format 按 kind 校验
```ts
// ExportJobPayload 增：
mediaKind: 'audio' | 'video';
// format 校验分流：audio → 'mp3'|'m4a'|'wav'（现状）；video → 固定 'mp4'
```
- **理由**：不把 `'mp4'` 塞进现有 format 联合类型——那会让所有 `format === 'mp3'` 式判断多一个分支负担；`mediaKind` 是用户意图，`format` 是实现细节，分开表达。
- 视频只给 **mp4 容器**（H.264 + AAC，兼容性最好）。⏳ 不做 mkv/webm 选项（无用户诉求）。

### D3 · ffmpeg 参数（三个变体；⏳ → **已全部实测收敛（2026-10-02）**，逐条见节末收口注记）
| 变体 | 视频流 | 音频流 |
|---|---|---|
| 音频（现状） | — | 重编码 mp3/m4a/wav |
| 视频·带音轨 | `-c:v libx264`（CRF 由 quality 映射） | **优先 `-c:a copy`**（实测兼容）；不兼容退 `-c:a aac` |
| 视频·纯视频 | 同上 | `-an` |
- 剪段沿用 `-ss/-to` 精确切（与音频同口径）；**merge 视频是技术最不确定点**：concat demuxer 要求同编码参数，分段各自重编码后 concat 是否花屏/音画偏移 **必须实测**；若 concat 不可靠，merge 视频降级方案 = 先各段产出再一次性 concat 重编码（耗时×2，如实告知用户）。
- `quality` 字段语义扩展为 CRF 档位（沿用现有 low/mid/high 键名），映射表写进 `export-args.ts` 并配参数快照测试。

> **收口注记（2026-10-02，实测报告 `.superpowers/sdd/2026-10-01-clip-works/ffmpeg-measure-report.md` A 组）**：本节 ⏳ 已全部实测收敛，裁决内容不变——
> ① **输入侧切分**：`-ss T -to T+D` 输入选项可用（A1 产物 v/a 双流均 10.000s 整）；
> ② **带音轨的音频流**：`-c:a copy` 直拷可行（A2，音频比视频长 5.3ms 属 AAC priming 正常现象），但只省 0.07s → 落地取 **AAC 重编码 `-c:a aac -b:a 192k`**（A1，时长精确 10.000s、无时间戳边界情况）——比本节原倾向（优先 copy）更稳；
> ③ **纯视频**：`-an` 只省约 2% 耗时（A3），照常实现、不单开参数路径；
> ④ **CRF 映射**：high=20 / mid(缺省)=23 / low=28（A4：4K 10s 体积 41.5/32.2/21.0 MB，三档耗时几乎相同）；
> ⑤ **merge**：逐段同参编码 → concat demuxer `-c copy` 成立（A5：0.46s vs 一次性重编码 42.89s，93×；总时长 180.000s、4500 视频帧分毫不差、0 decode error；段首必为 IDR，机理上不花屏）→ 本节的降级方案（一次性 concat 重编码）**不需要**；拼接点音画同步程序侧已验，人工听看复核项照实测报告裁决表①移交目验。

### D4 · 成品归属与聚合语义不变
- 视频成品同样写 `source_work_id`（D4 of clip-works），`product_count` **包含视频成品**（"成品 N 条"语义不变）；`total_sec` 同样累计。
- D22（导出前重查作品仍在）逐段校验逻辑**原样复用**。
- **删除作品连带删视频成品文件**——既有三条 DELETE 事务**不用改**（按行删，kind 无关），但它的测试要补"视频行也删干净"的用例。

### D5 · 前端分流
1. **导出区**：新增 Radio「导出内容」：`音频 / 视频（带音轨） / 视频（纯视频）`。选任一视频项时：格式 Radio（mp3/m4a/wav）**隐藏**（固定 mp4），其余（分多段/合并、导出按钮）不变。切回音频时格式 Radio 恢复。
2. **成品明细**：按 `media_kind` 分流——音频行 `<audio>`（现状）；视频行 `<video controls preload="metadata">` + 分辨率徽标（`720p`，来自 height；无则不显示）。**空态/标题/删除确认文案不变**（"成品"语义覆盖两种）。
3. **「预览音频」按钮**：只播**音频**成品（语义就是"听"）；该作品只有视频成品时禁用 + Tooltip「这个作品只导出过视频，可在下方成品列表直接播放」。
4. **hover 快速预览**（作品墙）：`WorkPreview` 的"只有音频的卡播 `latest_product_id`"分支——若最新成品是**视频**，用 `<video muted playsInline>` 播（静音纪律不变）。
5. **类型**：`AudioRow` 加 `media_kind: 'audio' | 'video'`、`width/height: number | null`；旧服务端未升级时字段缺失 → 按 `'audio'` 兜底（仅本地 dev 混跑场景，正式前后端同仓同发）。

### D6 · 体积与预期管理（诚实原则）
- 视频导出**慢且大**是事实：UI 不许假装轻快。任务抽屉/进度条已有；导出成功绿条文案对视频**加一句耗时提示**不做——按既有文案（"已导出 N 段"）+ 真实耗时由进度条本身传达。
- ⏳ 实测基准（plan Task 1）：用 `media-13`（21:30）导一段 60s 视频与合并全片，记录耗时与体积，写进验收基线。

## 4. 不做（YAGNI，与用户诉求对照后主动砍掉）

- 不做**字幕烧录**、多音轨选择、帧率/码率手动设置（quality 档位够用）。
- 不做**导出 mp4 之外的容器**（用户没要；mkv/webm 需求出现再议）。
- 不做**视频成品参与"预览音频"**（D5.3 已裁决按钮语义）。
- 不做**素材未下载时的视频导出**（`videoPath` 不在 → 既有 `existsSync` 失败路径原样兜住）。

## 5. 验收（人工目验清单，交用户）

1. 音频导出**完全回归**：mp3/m4a/wav × 分多段/合并，产物、标题、入库、播放、删除与改前一致。
2. 视频·带音轨：切一段 10s → mp4 能播、**有声**、画面与源对应时刻一致；入库挂作品；删除连带文件。
3. 视频·纯视频：同上但**无声**（播时确认音轨条不存在）。
4. 视频合并：3 段 → 1 条 mp4，段间无花屏/音画偏移（实测裁决点 D3）。
5. 成品明细：视频行能内联播放、有分辨率徽标；删除确认文案正确。
6. 作品墙 hover：只有视频成品的卡能静音预览。
7. 老库升级：迁移前旧库打开，音频成品一切照旧，`media_kind` 默认 'audio'。
