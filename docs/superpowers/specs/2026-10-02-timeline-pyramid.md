# Spec B · 时间轴缩略图/波形分级重构（2026-10-02）

> **状态**：草案，**待用户过目后才出实施计划**。
> **来源**：交接词 `docs/handoffs/2026-10-01-timeline-thumbnails-and-audio-lineage.md`（2026-10-01 已讨论完决策，Spec A 已落地、本 spec 一直空着）；用户 2026-10-02「轨道在滑动的时候并不顺畅」「之前整个轨道不是还有两种切换方式」。
> **前置**：N0 已修（胶片条参数/缓存自愈/探测失败明确失败），本 spec 建在它之上。

---

## 1. 目标（用户要什么，两句）

1. **看得清**：拖动/缩放时间轴时，画面采样随缩放**变密**——放大到某一段时，那一段的画面帧变多，而不是永远 12 格铺到底。
2. **两种切换方式**：时间轴可**缩放**（拉长拉短）也可**平移**（拖动视口），二者都流畅。

## 2. 事实（已实测/已核实）

1. **现状架构**：服务端一次性生成**一张** 1600×90 胶片条（12 格 tile）+ 一张 1600×120 波形，前端拉满容器宽。`DERIVED_FILM_TILES = 12`（`server/src/ffmpeg/derived-args.ts`）。
2. **采样密度瓶颈**：21:30 的片子 = 每格 107 秒。拖动时一格内画面不变 → 视觉「卡住」。**这是设计级，N0/N2 的快修无法解决**（N2 修复轮已向用户声明）。
3. **全量解码的代价（N0 实测）**：2.1GB / 21:30 全片解码一次 = **45–52 秒**。→ **「点开页面就为整片生成高密度缩略图」不可行**——分级 + 分段 + 视口优先不是过度设计，是实测逼出来的。
4. **N0 已建好的地基**：派生图缓存有 meta 自愈机制（sig 三关比对、inflight 去重、原子落盘）——本 spec 的多级/分段缓存**直接扩展这套机制**，不另起炉灶。
5. **波形现状**：`showwavespic` 一次性画整片 1600×120——波形不随缩放变密，放大后看不出局部细节。m2-workspace B2 backlog 明言「出现看不清波形细节的反馈时引入更细方案」——**该反馈已出现**（用户原话即 N2）。
6. m2-workspace 明确**不引 wavesurfer.js**（D6 裁决仍有效）：自绘路线延续。

## 3. 裁决（决策级；⏳ = Task 1 实测后收敛）

### D1 · 分级雪碧图（金字塔）
- **层级**（⏳ 确切级数待实测，起点提案）：
  - **L0 总览**：≈24–36 格铺满全片（现有 12 格的 2–3 倍；一次性生成，替代现有 filmstrip——**现有路由行为由它接管**）
  - **L1 中景**：每格 ≈ 8–15 秒，按**分段**生成（每段覆盖一个固定时间窗，如 128s）
  - **L2 近景**：每格 ≈ 1–2 秒，同上分段
- **分段雪碧图**：每段一张 `film-<id>-L<level>-<segIdx>.png`（横向 N 格），URL 寻址 `?level=&seg=`。缩放到某级时只请求视口覆盖到的段。
- **生成方式**：⏳ 逐格 `-ss` 定点抽帧 vs 分段解码。直觉上逐格 seek 快得多（不必解整片），但 seek 到关键帧的精度与耗时**必须实测**——这正是交接词定的硬门槛。

### D2 · 多级波形峰值
- 服务端一次性提取**峰值数组**（每像素/每 N 采样一个 min/max），存 JSON 或直接算好若干级（L0/L1/L2 每级一个峰值文件）；前端 **Canvas 自绘**波形（不再用整条 PNG）。
- 峰值提取方式（⏳ 实测二选一）：ffmpeg `showwavespic` 按级出图再前端读像素（绕）vs `astats`/`amovie` 直出数据（正）；倾向后者，以实测结论为准。
- 数据量估算进 Task 1：21:30 片子 L2 级峰值点数量与文件大小（超过 1–2MB 就降级为「按段生成」）。

### D3 · 前端交互（两种切换方式）
- **缩放**：Ctrl+滚轮 / 缩放按钮（+/- 档位，不搞无级平滑——本地工具够用且实现简单）。档位 = 级别 × 段内偏移。
- **平移**：按住空白区拖动 = 平移视口（**注意与 N2-c 刚落的「拖动定位」分权**——缩放态下拖动语义变为平移，缩放档位最小时保持拖动定位。切换规则要写死并注释，防两套手势打架）。
- **播放头**不随平移/缩放重绘错位（百分比定位沿用）。
- 段区块/拖边微调（N2-c 三区分权）在缩放态下**语义不变**。

### D4 · 缓存与失效（站在 N0 肩上）
- L0 接管现有 `film-<id>.png` 语义：meta sig 扩展 level 维度。
- L1/L2 段缓存：`meta` 记 level/seg/参数；**视口优先**——用户看到哪段才生成哪段；**空闲预取**——视口相邻段在 idle 时后台生成（`requestIdleCallback`，上限并发 1，不与前台任务抢 ffmpeg）。
- 素材替换/删除 → `invalidateDerived` 一并清所有 level/seg（扩展现有函数）。

### D5 · 失败与降级（诚实原则）
- 某段生成失败 → 该段显示**明确的占位**（斜纹 + 重试），**不用邻段内容冒充**。
- 短视频（< 5 分钟）只生成 L0+L1，不建 L2（⏳ 阈值实测定）——避免小文件也背上全套缓存。

## 4. Task 1 = ffmpeg 实测（硬门槛，交接词原文要求；先于一切实现）

产出一份实测报告（进账本），回答四件事，每件带数字：
1. **逐格 seek 抽帧耗时**（同一 2.1GB 源，抽 36 格 vs 全解码 45s 对照）。
2. **单段 L1/L2 雪碧图生成耗时**（一段 128s 窗口）。
3. **波形峰值提取**：方式对比 + 21:30 全片数据量。
4. **merge 无关但顺带**：`-c:a copy` 进 mp4 的兼容性（给 N1 spec D3 用，一次实测两份 spec 受益）。
**不设门槛不进 plan**：若实测发现逐格 seek 与全解码同数量级（说明 seek 不省），D1 改为「只做两级 + 段内按需」，spec 相应修订后再过目。

## 5. 不做

- 不引 wavesurfer.js（既有裁决）；不做无级平滑缩放；不做多轨；不做关键帧精确对齐（画面格只代表"这一格覆盖的时间段"，不承诺帧级精度——UI 文案如实）。
- **不动 N0 刚修的语义**：总览层仍"覆盖整段"（末格差一格是 tile 数学，接受）。

## 6. 验收（人工目验）

1. 21:30 素材：总览铺满全片（N0 语义保持）；放大 2 档后拖到任意位置，该段画面**明显变密**且段边界无跳变感。
2. 缩放/平移手势与拖动定位、拖边微调**互不抢**（N2-c 三区在缩放态仍成立）。
3. 冷启动（全新素材）首屏 < 2s 出总览（L0），L1/L2 后台补——**不再出现 N0 修复前的 50s 白等**。
4. 波形放大后能看到局部疏密（不再是均匀一条）。
5. 生成失败段有明确占位与重试，日志页可见原因。
